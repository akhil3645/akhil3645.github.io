DESIGNERSalesforce Spiff — Plan Builder & Formula Editor

Salesforce-owned since Feb 2024 (~$419M). Native ICM inside Sales Cloud. The engine room is Designer: plans hold payout rules; rules point at calculated fields on datasheets/worksheets where formulas actually live. Screenshots are official Trailhead/vendor documentation UI.

1. Designer — Plans and Data tabs

Designer landing: Plans tab in the left panel with folders for plans, worksheets, datasheets, tables. Context selector top-left. Data tab: source objects and their fields (Fields/Filters) — this is where Salesforce objects are exposed to calculations. Calculated fields you create appear alongside source fields.

2. The plan page and payout rules

Real UI — plan "Spiff Corporate AE Plan": tabs ASSIGNED USERS | RULES | CUSTOM FIELDS, with Assign Users, Active/All filters, Download, Search, and the Plan Assignments table (Name, Email, Role, Effective As Of/Until). Top nav: COMMISSIONS, TEAMS, PLANS, QUOTAS, DOCUMENTS, DATA SOURCES, REPORTING, ADMIN, and the DESIGNER button. Plan View showing multiple **payout rules** attached to the plan. A rule has: name, Payout Amount (a field from a datasheet/worksheet), Effective As Of/Until, and a Payout Rule Total. What-If? and Ghost Rule variants exist. Rules can be created from a field via right panel PAYOUT RULE | Create Payout Rule.

3. Where formulas live — datasheets and worksheets

Datasheet: pick a Salesforce object + data filter, then add fields — line-by-line per-record calculations. Select a cell/field and type the formula in the formula bar; names turn green/yellow with tooltips. Worksheet: spreadsheet for lump-sum/single-value calculations (e.g. quota, rate, totals) feeding rules. Cross-sheet references look like WorksheetB!TotalARR or DatasheetA!ARR. The right-panel function library opens on any function with description/syntax/args — here tier_payout. Functions include tier_payout(rangeTableValue, table, tiebreak, "returnColumn"), sum(), if(), filter(), contains(), amounts_from(), mpercent(). A RepCommissionPayout column = ARR × tier rate — the formula shown inline in the field editor.

4. Rate/accelerator tables and how formulas consume them

Range table: Lower Bound / Upper Bound rows with year-named rate columns (e.g. 2024/2025 rates) — the table tier_payout reads.
Accelerator table used by the tier formula.
tier_payout(...) with a dynamic return column (e.g. CurrentYear) so the rate table switches columns per period.
How formulas get inserted into plans (Spiff model): formula → a calculated field/column on a datasheet (line-by-line) or worksheet (lump-sum) → the plan's payout rule sets its Payout Amount to that field → the rule pays out on effective dates. Example chain: TieredARRPayout_Payout = ARR__c * EarnedRate_…, where EarnedRate_… = tier_payout(TotalARRAttainment_…, SpiffCorporateAE_Table, false, "2024 CorpAE Rates").

5. Trace view — click any payout and see the math

Real trace of a payout: Payout Rule "Tiered ARR Payout" resolves to TieredARRPayout_Payout = USD 1216.98; its Variable shows ARR__c * TieredARRPayout_Worksheet|EarnedRate_TieredARRPayout = $20,283.00 * 6.00%; EarnedRate expands to tier_payout(TotalARRAttainment_TieredARRPayout, SpiffCorporateAE_Table, false, "2024 CorpAE Rates") = 0.06; the Table shows the actual tiers (Tier 2 50–100% → 6%, Tier 1 → 4%, Tier 3 100%+ → 8–10%). Every step is clickable. Deal-level trace: Commission, Deal Amount, Deal Booking Date, Split Percent and Split Amount, ARR, Total Contract Value, Contract Length, and the calculated CommissionOnPayment_CommissionRate (3.00%) and CommissionOnPayment_Commission (USD 1132.38). Rule Trace view in Designer — the vertical calculation chain for a payout rule (same mechanism, admin-side).
